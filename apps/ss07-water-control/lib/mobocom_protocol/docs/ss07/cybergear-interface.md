# SS-07 CyberGear 云台电机接口方案

三轴云台使用CyberGear电机，由ESP32-G通过原生CAN控制。本文把用户提供的电机手册与串口说明转换为项目接口约定，用于驱动开发、台架联调和故障验收。电机CAN、调试器串口封装和PC mobocon至接收器的0x22 UDP分别实现；Control网络迁移不修改电机私有协议。

## 2 节点规划

| CAN 节点 | 建议 ID | 识别与标定 |
| --- | --- | --- |
| ESP32-G 主站 | `0x00` | CAN ID，与Control UID及当前IP独立 |
| Yaw | `0x01` | MCU 唯一标识、零位、正方向、机械范围 |
| Pitch | `0x02` | 同上，并核验重力负载与失电姿态 |
| Roll | `0x03` | 同上 |

电机初始 ID 可能相同，首次配置逐台接入、读取唯一标识、分配 ID 并验证，避免同时向多个重复 ID 设备写配置。配置后重启确认 ID 是否保持，不推断所有配置都持久化。

G 首版采用 ESP32 自带 TWAI/CAN 控制器加外部收发器。USB-CAN/串口-CAN 适配器仅用于台架观察或厂家工具；同一 CAN 总线调试时停用生产运动来源，避免两个主站同时驱动。

## 3 CAN ID 与数据编码

常见管理帧、单参数读写帧的 ID 构造为：

```text
can_id = (communication_type << 24) | (master_id << 8) | motor_id
bit28..24: 通信类型
bit23..8: 类型相关字段，管理帧中主站 ID 位于 bit15..8
bit7..0: 目标电机 ID
```

此公式不能直接用于所有报文：类型 1 在 bit23..8 携带量化力矩；类型 2 在该区域携带电机 ID、故障与状态；类型 7 增加新 ID。实现按类型编码与解析，并显式设置扩展帧标志和 DLC=8，不依赖 C/C++ 位域的编译器布局。

### 3.1 首版使用的通信类型

| 十进制类型 | 用途 | 实现约束 |
| --- | --- | --- |
| 0 | 读取设备 ID 与 64bit MCU 唯一标识 | 建立固定身份映射 |
| 2 | 运行状态反馈 | 解码角度、角速度、力矩、温度、模式与故障位 |
| 3 | 使能 | 确认有效零位、参数、模式和无故障后允许 |
| 4 | 停止运行 | 正常停止全 0 数据；Byte0=1 为清故障，分开操作 |
| 6 | 当前位置设机械零位 | Byte0=1；掉电丢失，只允许明确标定流程调用 |
| 7 | 修改电机 ID | 只在维护、禁止运动状态执行 |
| 17 | 单参数读取 | 参数索引在 Byte0..1，响应数据在 Byte4..7 |
| 18 | 单参数写入 | 参数索引在 Byte0..1，Byte2..3=0，值在 Byte4..7 |
| 21 | 故障与预警 | 保留原始故障字并映射项目故障 |

类型 1 运控模式暂不向普通用户开放，类型 22 波特率修改也不纳入运行 API。首版先使用位置与速度模式，后续需要惯性稳定时再定义 IMU 与闭环方案。

### 3.2 参数索引

| 索引 | 名称 | 类型和单位 | 项目用途 |
| --- | --- | --- | --- |
| `0x7005` | run_mode | uint8，1 位置、2 速度、0 运控、3 电流 | 首版仅开放 1/2 |
| `0x700A` | spd_ref | float32，rad/s，手册范围 -30 至 30 | 速度目标，项目限制明显低于协议极限并由台架定稿 |
| `0x700B` | 转矩限制 | float32，N·m，0 至 12 | 按机械负载定稿，保持厂家保护配置 |
| `0x7016` | loc_ref | float32，rad | 位置目标，遵守项目机械限位 |
| `0x7017` | limit_spd | float32，rad/s，0 至 30 | 位置模式最大速度 |
| `0x7018` | limit_cur | float32，A，0 至 23 | 位置/速度电流上限，按负载验证 |
| `0x7019` | mechPos | float32，rad | 负载端计圈机械位置 |
| `0x701B` | mechVel | float32，rad/s | 负载端速度 |
| `0x701C` | VBUS | float32，V | 母线电压遥测 |

索引采用小端；float32 按 IEEE 754 小端显式序列化，uint8 仅占 Byte4，其他数据字节清零。类型 2 的 16bit 量化字段按高字节在前解析的实现假设需要与实物反馈交叉确认；不能对整套协议统一使用单一字节序。

`0x7019` 等扩展参数在手册中有固件版本限制，启动探测后逐项确认可读能力。类型 17/18 的参数列表与调试器 `0x2000/0x3000` 表并非同一个索引空间，不把 `CAN_TIMEOUT=0x200C` 直接当成已支持的类型 18 写入参数。

### 3.3 帧样例

下面两个样例均为设置电机 1 的位置模式，不使能、不写运动目标。

```text
生产建议主站 ID=0x00
CAN ID: 0x12000001
DLC: 8
DATA: 05 70 00 00 01 00 00 00

用户 Word 示例主站 ID=0xFD
CAN ID: 0x1200FD01
DLC: 8
DATA: 05 70 00 00 01 00 00 00
```

主站 `0xFD` 是提供材料中的示例；手册调试配置表对主站 ID 的范围描述与此示例存在差异。本项目先选表中范围内的 `0x00`，使用实物验证反馈目标地址，不将 `0xFD` 固定为生产要求。

写 `loc_ref=0.5rad` 的数据区为 `16 70 00 00 00 00 00 3F`，其中 `00 00 00 3F` 为小端 float32 的 0.5。项目 API 使用度，转换为电机 rad 后再编码；手册已经给出负载端位置字段，不能默认再除以内部 7.75。外部额外传动比单独标定。

## 4 USB-CAN 串口封装

用户 `串口协议说明.docx` 的样例为：

```text
41 54 | 90 07 E8 0C | 08 | 05 70 00 00 01 00 00 00 | 0D 0A
```

调试适配器使用 `41 54` 帧头与 `0D 0A` 帧尾，中间 4 字节适配器字段按该样例大端表示，换算为：

```text
adapter_id = (can_id << 3) | 0b100
(0x1200FD01 << 3) | 4 = 0x9007E80C
(0x9007E80C >> 3) = 0x1200FD01
```

`08` 是 CAN 数据长度。ESP32 原生 CAN 发送 `can_id=0x1200FD01`、扩展帧、8 字节 payload；不左移 ID、不添加 AT 帧头/尾，也不发送这 17 字节串口包到 CAN 总线。

故障排查文档中的串口921600与CAN1000000属于调试转换器的两侧参数，和主控至ESP32的UDP网络无关。文档所列上位机版本及固件文件为资料中的排查条件，是否适用于实际适配器/电机需核对；升级只在维护流程中执行，不作为自动连接恢复动作。

## 5 初始化与运动流程

1. 上电 G 保持禁止运动，初始化 CAN 1Mbps 扩展帧接收，读取三个电机身份和状态。
2. 检查节点映射、反馈故障、母线电压和温度。旧运动目标、旧控制会话失效。
3. 读取配置能力，建立项目标定零位。机械零位易失，不在任何未知姿态自动发送“当前角度置零”。需要外部原点或人工对位时显式进入标定流程。
4. 电机停止状态下配置所需 run_mode；参数回读可用时校验，类型 18 的普通反馈不能单独证明目标参数已写入。
5. 设置经过验证的速度/电流/机械范围限制，尽可能在使能前写入限制。手册示例在使能后设置部分限制，是否允许前置写入需台架确认；不支持时按手册顺序在受控试验中完成，不使用上一次目标作为初始运动目标。
6. 取得有效控制权后发送使能，确认状态，再提交新的受限目标。
7. 位置操作读取实际位置，按约定误差与持续时间判定到达；速度操作持续发送新鲜目标，监督反馈与超时。
8. 切换位置/速度模式时先停止，确认状态，再改模式、配置限制、重新使能；普通接管优先保持原模式，避免不必要的模式切换。

类型 2 反馈角度按手册量化范围 -4π 至 4π 解码，可用 `q/65535×(8π)-4π`；角速度按 -30 至 30rad/s，力矩按 -12 至 12N·m，温度值除以 10。对反馈的物理合理性、帧类型、节点及时间进行校验，过期反馈不能用于保持位置目标。

## 6 失效保护与机械标定

失效响应按来源区分：摇轮有效输入过期按手动策略停止；PC编辑和播放均持续刷新目标；Control断线按每资源目标有效期及来源租约安全停止，接收器不直接检测时码失效。按各轴定稿的降速/保持/停止措施执行。G 失效或 CAN 物理断开时依靠电机自身已验证的通信超时行为或独立保护机制处理，不能依赖失效节点再发送停止帧。

`CAN_TIMEOUT`必须确认写入方式、单位、触发条件、是否对位置/速度模式都有效、是否易失，以及触发后扭矩是否保持。台架测试依次覆盖“停止PC上行Control UDP”“停止CAN发包”“切断CAN线”“G固件阻塞/复位”，分别记录检出、制动与负载姿态。在此之前该故障验收项保持未通过。

云台的 Pitch/Roll 负载需要支撑与配平。类型 4 停机和电源断开后能否保持姿态取决于机械与驱动状态，不声明具有机械自锁。机械轴限位、额外传动、线缆扭转限制与相机重心先确定，再设置软件限位。

温度告警和过温阈值保留厂家规定并验证遥测口径，不用控制板最大温度代替环境允许温度。电源按 16 至 28V 全工况、满电和制动回馈核验。

## 7 手册实现疑点与台架检查

| 疑点 | 处理 |
| --- | --- |
| 运控位置范围正文为 ±4π，代码示例为 ±12.5 | 首版不使用运控模式；后续加入前用厂家工具/反馈对齐量化边界 |
| `motor_enable` 示例先写 master_id，后又将同一 ID 数据字段置 0 | 实现按协议 ID 表明确编码，payload 单独清零；用非零主站验证收发地址 |
| 调试示例主站 0xFD 与参数表范围不一致 | 生产先使用 0x00，并记录固件实际允许范围 |
| CAN_TIMEOUT 缺少单位与动作 | 不假设毫秒；向厂家确认并完成失联测试 |
| 表中电流口径混有峰值与驱动器电流 | DC 母线实测确定电源与线束，不直接换算系统总功率 |
| 机械零位与模式参数掉电丢失 | 启动检查与重建配置，不恢复旧运动目标 |

首轮交付应包含：三轴唯一标识与 ID 表、固件版本、CAN 抓包、位置/速度读写向量、单位转换与零位配置、软限位、模式切换测试、失联/重启记录，以及满负载供电与温升测量。
