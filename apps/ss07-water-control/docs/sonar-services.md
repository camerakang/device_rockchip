# 声呐服务与恢复接入（0.10.0 开发增量）

2026-10-23。声呐公共框架和数据盘归档现已接入 systemd 安装配方、API 读取路径、配置状态确认和应用安装事务。当前为源码与隔离暂存验证，尚未发布新应用包或 IMG，未在实际板端创建账号、启动服务或打开串口。

## 服务与权限

`systemd/ss07-sonar.service` 使用独立 `ss07-sonar` 用户，主组为 `ss07-recordings`，附加 `dialout` 与 `ss07-state`。仅开放 USB tty 字符设备和 Unix 通信；声呐发送权限只供后续经确认的厂家轮询驱动使用，时码服务继续单独以只读设备权限运行。当前厂家注册表为空，默认配置下进程保持 `UNAVAILABLE / sonar_not_configured`，不打开 tty、不启动归档写者，不产生测距值。

安装配方增加 `/var/lib/ss07/sonar`（2750，`ss07-sonar:ss07-recordings`）。诊断历史为 `samples.sqlite`，归档索引为 `archives.sqlite`；API 使用读取组和只读目录挂载读取这两个文件。所有文件均由实际工作进程按需初始化，不复制测试数据库到镜像。target、初始化门控、升级停启顺序及独立启动恢复 drop-in 已包含声呐服务。

数据盘尚未连接，保持视频与声呐归档关闭，UUID 为空。接入真实卷时，管理员须先核验配置 UUID、精确挂载与目录身份，再准备以下所有者和权限；不能对尚未挂载的 `/data/ss07` 创建目录来代替数据盘：

| 已核验卷中的目录 | 所有者/组 | 权限 |
| --- | --- | --- |
| `/data/ss07` | `ss07-storage:ss07-recordings` | 2750 |
| `/data/ss07/recordings` | `ss07-storage:ss07-recordings` | 2750 |
| `/data/ss07/recordings/sonar` | `ss07-sonar:ss07-recordings` | 2750 |

独立声呐账号不能在录像账号拥有的 2750 父目录中创建子树，因此声呐目录必须在启用归档之前准备。后续声呐实例和分段由声呐进程创建，API 只读。tmpfiles 不创建这些数据盘目录。缺少权限时归档报告异常，不调整整卷权限，也不退回系统盘。离线归档维护也应使用同一服务身份及组，避免以其他身份新建不可写索引；现有命令不会自动修复所有者。

这些权限是待部署的安装要求。隔离进程联测共用开发用户，systemd 静态检查不证明实际 UID、设备 cgroup 或实盘目录权限已经验收。

## 配置与健康确认

配置消费者加入 sonar，启动顺序位于只读时码之后，停止时先停声呐再停时码。无厂家 Profile 时，只接受与当前配置一致的明确不可用原因作为“配置已加载”；不会把 `RUNNING` 字样当作设备已连接。将来接入经确认的 Profile 后，健康确认要求串口已连接，启用归档时还要求归档处于 `RECORDING`。

禁用归档时，视频分段时长等存储变化不重启声呐。配置协调器目前继续拒绝声呐参数变更、归档开启以及已启用归档的存储变化，返回 `sonar_driver_unavailable`；这是厂家驱动缺失的明确边界。安装配方接入不代表厂家协议、串口地址或发包时序已实现。

## 安装事务与兼容性

新安装事务同时检查声呐诊断库与归档索引的 application_id/schema，并在停止消费者后进行一致备份。恢复代码不覆盖升级后新增加的数据；发现未知声呐 schema 时保留门控与原文件，要求明确的迁移方案。

独立恢复助手兼容旧事务的三个数据库类别；新事务加入两个声呐类别，拒绝仅包含一半新类别或类型错误的契约。`file-N` 备份使用的原文件序号全部保留，新服务文件附加在旧表末尾，避免旧配置备份被错误当作单元文件恢复。旧事务恢复不会打开或删除它原先没有管理的声呐数据库。这不授权跨数据契约升级。

0.10.0 配置兼容修订为 2，JSON envelope 仍为 schema 1。后续已实现[0.9↔0.10 迁移与恢复](sonar-migration.md)，按目标版本选择单元集合，并在降级前检查归档关闭、历史完整性及配置摘要。本文 223 项测试是服务接入阶段的历史证据；候选应用包及跨契约联测以迁移验证记录为准。既有 0.9.0 包与 0.6.1 IMG 保留。

## 验证

验证覆盖新鲜配置确认、无厂家时拒绝虚假运行状态、归档状态门槛、关闭归档时避免无关重启、旧备份序号、旧事务保留声呐数据、新事务双库核验以及未知 schema 保持门控。全量 223 项测试在 CPython 3.8.20 和隔离 ARM64 CPython 3.8.10 通过，11 种 service 模板和 target 通过目标 systemd 245 静态解析。原生进程/HTTPS/浏览器联测通过配置应用、监听端口占用自动恢复与重新登录后六路 WebRTC 解码；媒体和录像进程身份保持，恢复检查时每路已有 21 个完成片段。声呐始终保持未配置且归档关闭。测试环境前两次缺少 x264enc/h264parse 插件，补齐隔离的测试插件与解析库后通过，未安装主机软件包。日志和摘要见[验证记录](evidence/sonar-services-validation.json)。

归档文件与网页的数据语义见[声呐归档](sonar-archive.md)。厂家协议、真实 USB tty 与 RS485 接线、实际 UID/权限、共享数据盘并发/掉电和新版本完整镜像仍待后续实现或设备验收。
