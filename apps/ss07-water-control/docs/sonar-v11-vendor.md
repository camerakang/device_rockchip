# RK3588 接入五路声呐板

适用版本：Sonar Drive V1.1，CH1 已飞线至 GPIO4，固件 `sonar_v11_ch1_gpio4`，距离协议 `v=1`。更新日期：2026-11-20。

**接线只用一条 USB 数据线：声呐板 U10（USB 转串口）→ RK3588 的 USB Host。** 声呐板保留外部工作电源。U9 是烧录和调试口，不是本文使用的数据口。RK3588 不需要安装 PlatformIO，不需要接 GPIO，也不使用 Wi-Fi。

## 1. 首次联调：从接线到收到五路数据

1. 将交付包解压到 RK3588 的可写目录，进入包含 `tools/` 的目录。保持 `rk3588_sonar.py` 和 `accept_v11.py` 在同一个 `tools/` 目录，后者会导入前者。
2. 准备 Python 3 和 pySerial。Debian/Ubuntu 系统可执行 `sudo apt install python3-serial`；其他系统使用对应的包管理器。用 `python3 -c 'import serial; print(serial.VERSION)'` 确认依赖可用。
3. 插入 U10，用 `python3 -m serial.tools.list_ports -v` 对比插拔前后的设备。板上桥接芯片为 CH340N，台架识别为 `1A86:7523`。有多个同型号设备时须按插拔或 USB 物理路径确认，不要只凭 VID/PID 或 `ttyUSB0` 猜测。量产部署优先使用现场确认的 `/dev/serial/by-path/...` 稳定路径。
4. 运行以下命令，`PORT` 换成实际节点。固件上电即轮询，不需要先发启动指令：

```bash
PORT=/dev/ttyUSB0
python3 tools/rk3588_sonar.py "$PORT" --seconds 5
python3 tools/accept_v11.py "$PORT" --gpio4-rework --seconds 60 \
  --log "sonar-$(date +%Y%m%d-%H%M%S).jsonl"
```

**通过判据：** 第二条脚本输出 `stream_pass: true`、`bad: 0`、`gaps: 0`，退出码为 0。五路都应出现，正常每路约 120 帧/分钟；脚本允许起止边界和少量速率余量。`--gpio4-rework` 对本板必填，否则验收脚本会期待旧板的 CH1 状态。日志文件必须是新文件。验收时只运行一个串口进程，不发诊断命令。

只验收数据通路时不用放入水中，`no_echo` 可以通过。**这不等于距离精度、弱回波性能或水下有效量程通过。**

## 2. 业务程序如何使用距离

串口参数：**115200、8N1、无流控**。每次读取以 LF 分隔的一行 JSON，不假设一次 `read()` 对应一帧。五个通道顺序轮询，每 100 ms 约一帧；同一探头约每 500 ms 更新一次。通道与实物插座的对应关系为 **CH1=CN4、CH2=CN2、CH3=CN3、CH4=CN5、CH5=CN6**，不是插座编号顺排。

距离帧示例（数值仅用于说明协议）：

```json
{"v":1,"seq":152,"ms":15210,"ch":2,"id":185,"state":"ok","mm":1998,"thr_mv":800}
```

| 字段 | 上位机应如何解释 |
|---|---|
| `v`、`ch` | 协议版本 1；通道 1～5。每路单独存储距离、状态、最后接收时间。 |
| `seq`、`ms` | 全板帧序号、板端本轮开始时的毫秒计数。均为 32 位无符号值，可回绕，重启后重新计数。`ms` 不是 RK3588 的系统时间。 |
| `id` | TUSS4470 正常为十进制 185，即 `0xB9`；`-1` 表示未读到 ID。 |
| `state`、`mm` | 仅 `state="ok"` 且 ID 正常时使用整数毫米值；所有非 `ok` 状态的 `mm` 均应为 `null`，不是 0 米。 |
| `thr_mv` | 该路软件阈值下限，单位 mV。固件可根据本次基线噪声抬高实际门限。 |

`no_echo` 表示完成采样、检测到发射包络，但未得到合格的距离；`no_burst` 表示没有识别到发射包络。`spi_error`、`wrong_id`、`config_error` 对应芯片通信或配置异常；`adc_init_error`、`adc_error`、`clock_error`、`timing_error` 对应采集或时序故障。正式飞线版出现 `no_adc_pin` 时，先查是否误烧了未飞线版固件。

**不要沿用旧距离。** 收到非 `ok` 帧就清空该通道距离；通道超过 1.5 秒未收到可解析的距离状态帧也要清空。示例接收脚本会在超时后输出一次 `{"event":"offline","ch":2,"mm":null}`，这是 **RK3588 本地事件**，不是声呐板报文。串口断开时脚本重试同一节点；正式应用还应跟踪全板 `seq` 的缺号和重启。需要持续运行示例时，去掉 `--seconds 5`。

## 3. 控制、阈值和波形

### 现场参数（需含 `get` / `set` 的固件）

先停止占用 U10 的接收服务，用 `python3 tools/sonar_params.py "$PORT" 2` 读取 CH2 当前配置。
例如 `python3 tools/sonar_params.py "$PORT" 2 blank_us 1500` 修改 CH2 盲区；工具会再次查询并核对。
设置只影响指定通道，下次该路采集生效，成功写入 NVS 后重启保留。请先记录原值，调试结束按原值恢复。
在集成服务内部应复用同一串口：发 `get 2\n`，读取带 `"params":2` 的对象（没有单独 ACK）；
发 `set 2 blank_us 1500\n`，等待 ACK 后再 `get` 确认。旧固件仅支持 `thr` 等旧命令，不支持批量配置或新查询。

| 键（均为十进制整数） | 默认值；范围 | 何时改 |
|---|---|---|
| `thr_mv` | 800；200～3200 mV | 噪声误报时调高；弱回波漏报时结合包络调低。实际门限仍受基线噪声限制。 |
| `blank_us` | 1300；200～10000 µs | 发射余振被误判时增大；盲区内的近目标也会被排除。 |
| `range_mm` | 20000；500～20000 mm | 排除作业范围外回波。限制的是补偿前距离，不改变采样长度或轮询周期。 |
| `sound_mps` | 1480；1400～1600 m/s | 使用现场水体的声速换算距离；五路在同一水体时通常设成相同值。 |
| `offset_mm` | 0；−1000～1000 mm | 已知距离标定或探头安装基准补偿。正值增大输出；补偿后超出 0～20000 mm 不报有效距离。 |
| `width` | 2；1～16 点 | 抑制窄噪声尖峰时增大；过大可能漏掉窄回波。名义采样间隔 50 µs。 |
| `gain_x10` | 150；仅 100、125、150、200 | 接收前置增益（实际为 10、12.5、15、20 倍）；结合包络调节，避免饱和。 |

参数组合还需在盲区和固定采样窗口之间留出回波宽度，否则返回 `{"ack":false}`，原配置不变。
例如从默认量程切换到 1400 m/s 时，应先缩小量程，再改声速。200 kHz 发射频率、脉冲数、
驱动电源和 SPI 引脚与现板匹配，不开放为现场设置。

命令是小写 ASCII，每条以 `\n` 结尾。由**同一个持有串口的进程**写命令并读回复；调试前先退出接收和验收脚本。普通距离帧与命令回复共用 U10，不能假定发命令后读到的第一行就是回复。

| 发送 | 回复与效果 |
|---|---|
| `pause` / `run` | 暂停或恢复五路轮询。返回 `{"ack":true}`；暂停不写入存储，重启自动运行。 |
| `thr 2 900` | 将 CH2 阈值下限改为 900 mV。允许 200～3200，按通道保存到 NVS，重启保留。成功后用下一条 CH2 距离帧的 `thr_mv` 确认；恢复默认值发 `thr 2 800`。 |
| `wave 2` | 请求 CH2 下一次采集的包络，仅回给发起请求的端口。`ack` 表示请求已接受，不表示波形已经完整送达。暂停时须先恢复轮询。 |

不支持的命令或无效参数返回 `{"ack":false}`。每个端口只保留一个待处理的波形请求，请收齐后再请求下一路。`rk3588_sonar.py` 面向日常距离数据，会过滤 `ack` 和波形行；诊断程序需要读取原始 JSON 行并按键分类。

波形行的 `wave` 是通道，`seq` 对应同一次测距帧，`i` 是本块起始下标，`n=585` 是总点数，`mv` 是以毫伏为单位的包络数组。每块最多 16 点，按 `(wave, seq)` 分组，从 `i=0` 连续拼接到 585 点；丢块应丢弃整条曲线。`period_us=50` 是名义采样周期，前 16 点是发射前基线。这是回波包络，不是 200 kHz 换能器载波。收到 `{"wave_error":"capture"}` 表示本次采集无可用波形。

## 4. 故障定位与验收边界

| 现象 | 先检查 |
|---|---|
| 插入后没有串口设备 | 是否接 U10、RK3588 端是否为 Host、USB 线是否支持数据；查看 `dmesg` 的插拔记录，确认系统有 CH340/CH341 驱动。 |
| `Permission denied` 或数据被读走 | 检查 `ls -l "$PORT"` 的实际设备组和账号权限；关闭占用同一口的串口终端、接收脚本或后台服务。 |
| 有串口但五路全静默 | 确认外部工作电源和设备节点；若此前调试用过 `pause`，从 U10 发送 `run\n`。只重新插 USB 不一定会让仍有外部供电的声呐板重启。 |
| 五路有帧，但水下数值不符 | 确认插座、探头朝向、目标实距和盲区；先看包络再调阈值。`ok` 仅说明固件选中了候选回波，不等于目标已识别。 |

**水下实距要另做验收。** 例如只对 CH2 使用距探头面 2000 mm 的平面靶，且现场约定允许误差 100 mm，可在第 1 节验收命令中追加 `--target 2:2000 --tolerance-mm 100` 并使用新日志名。指定通道的每一帧都必须有距离且满足容差。该距离和容差是示例，不是已测指标。

交付时的台架记录：正式固件已在 U9 连续输出 30 秒，共 300 帧，五路各 60 帧，无坏帧、无缺号；五路各导出 585 点包络。CH1 阈值经过修改、重启读回并恢复到 800 mV。**以上不是 RK3588 实机验收记录。** 接板后请保留第 1 节在 RK3588 上生成的原始日志和验收结果。
