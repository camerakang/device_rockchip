# SS-07 RK3588 视频与声呐系统独立设计

本软件独立运行于 LubanCat-4，从当前 SDK 编译镜像。负责六路视频、五路声呐、监看、录像、状态和配置。接收器运动控制、跟焦固件和 mobocon 开发均不属于本软件；RK 重启不会改变云台接收器控制权。RK以独立只读RS485接口接收0x12时码，关联录像和声呐记录；UTC和外部时码分开保存，不改变电机控制或证明曝光同步。本文定义设计约束；已实施与未验收内容见 [交付跟踪](delivery-progress.md)。

## 范围与硬件输入

| 输入 | 处理 | 必须核验 |
| --- | --- | --- |
| SDI 摄像机 → SE2017 → Ethernet | RTSP 拉流/代理，录像和分发 | 编码器地址、模式、码率、供电 |
| 五路 USB 相机 → 独立供电 Hub | V4L2 H.264 原生采集 | 原生模式、唯一身份、真实 USB 拓扑 |
| 五个 RS485 声呐 → USB-RS485 | 厂家驱动、轮询、统一读数 | 型号、地址、协议、周期与声学互扰 |
| RS485时码器 → 独立USB-RS485时码接口 | 只读解析与记录时间映射 | 0x12格式、接线、接收时刻误差与源epoch |
| 船岸 Ethernet | 浏览器监看、状态和录像读取 | 实际距离、卷缆、接头、吞吐 |
| 录像介质 | 分段录像、索引与保留 | 挂载、容量、写速和掉电行为 |

建议初始模式为 SDI 1080p30/H.264/6Mbps，五 USB 各1080p25/H.264/3Mbps；设备不支持时根据枚举结果修改，不假定商品“300万”意味着这些模式。合计21Mbps，8小时约75.6GB，加20%余量约90.7GB，另留系统与日志空间。单个六路订阅端带30%余量约27.3Mbps。所有参数在设备测试后冻结。

USB 原生 H.264 直通优先；MJPEG/YUYV 转码须先验证 MPP 与总线预算，不能默认五路软件编码。WebRTC 用于浏览器实时监看，RTSP 供原生客户端，浏览器兼容性按实际 profile/GOP 测试。录像候选 fMP4、约1秒part/5分钟segment；最终以恢复和回放测试定稿。

## 1 RK3588 进程与模块

| 进程 | 内部模块 | 输入与输出 | 故障处理 |
| --- | --- | --- | --- |
| ss07-camera@front/back/left/right/down | 设备定位、模式设置、采集、H.264 解析、发布、健康 | V4L2 → 本机媒体服务 | 单通道退出重启；持续失败进入退避 |
| ss07-mediamtx | SDI RTSP 拉取、USB 流接入、WebRTC/RTSP 分发、分段录像 | 六路压缩视频 → 客户端/录像文件 | 重启影响六路分发；采集端重新建立发布连接 |
| ss07-sonar | 串口、厂家编解码、公平轮询、有效性、状态快照 | 五个地址 → 统一读数 | 一个超时不占用下一节点无限等待 |
| ss07-timecode | 只读串口、帧验证、时码质量、本机时间映射 | 0x12 → 有界状态/映射事件 | 失时/重启仅标记质量，录像继续 |
| ss07-video-api | HTTP、事件推送、配置校验、状态聚合、录像查询、网页 | 服务状态 → 岸端 | 重启不停止采集/录像；重连先发快照 |
| ss07-storage | 完成片段索引、空间策略、导出、片段锁定 | 录像目录 → 索引与容量告警 | 索引重建；禁止删除正在写入的片段 |

USB 采集建议用 C++ 与当前 SDK 的 GStreamer/V4L2 组合，原生 H.264 路径不插入解码器。API 与声呐建议使用 Python 3 独立服务，界面使用 TypeScript；这些是项目实现选择，具体依赖版本在首次构建前锁定。媒体服务使用固定 ARM64 版本及校验和。首版仅接入已验证的直通管线，转码作为按设备能力开放的独立模式。

相机状态机为 ABSENT → OPENING → STREAMING；读帧/发布失败进入 RECOVERING，模式不支持进入 CONFIG_ERROR。建议重试间隔 1/2/5/10 秒，最高 30 秒；连续稳定运行后恢复起始间隔。系统服务重启限额与通道内部重连分开，避免高频崩溃循环。

每个流限制缓冲的字节数和时间跨度；候选上限为该通道约 1 秒码流，实测后冻结。积压恢复需要新的随机访问点及参数集，不能从任意 P 帧继续。采集健康、发布健康和订阅端播放健康分别统计，不以进程仍存在判定画面正常。

## 2 RK 配置与持久化

| 文件或目录 | 内容 | 更新方式 |
| --- | --- | --- |
| /etc/ss07/system.json | schema_version、设备名称、网络与日志策略 | 校验后写临时文件并原子替换 |
| /etc/ss07/cameras.json | 固定通道、身份匹配、模式、码率、GOP、媒体路径 | 一次仅应用受影响通道 |
| /etc/ss07/sonars.json | sensor_id、方向、总线地址、厂家驱动、超时与周期 | 总线暂停轮询后应用，不与旧配置交叠 |
| /etc/ss07/timecode.json | 稳定时码串口、只读配置、延迟校准与映射记录策略 | 校验后重开时码服务，标记新映射段 |
| /etc/ss07/storage.json | 录像目录、容量阈值、保留策略 | 下个清理周期应用 |
| /var/lib/ss07/catalog.sqlite | 完成录像、锁定状态、配置变更记录 | 单写者事务；丢失时扫描重建录像索引 |
| /data/ss07/recordings | 原始分段录像 | 完成后索引，挂载缺失时禁止落到系统盘 |

相机身份匹配优先唯一序列号，其次固定 Hub 端口物理路径；相同无序列号设备不能仅按 VID/PID 区分。开机检测重复绑定并报错，禁止把左右相机悄悄交换。声呐 USB 串口使用稳定设备链接，检查厂家地址冲突。

配置的 draft、校验、持久化和实际生效状态分开。生效失败报告具体通道并恢复原配置；网页不能显示尚未应用的值为运行值。批量变更不承诺跨服务原子生效，返回逐项结果。设备密码独立保存，不出现在配置导出中。

## 3 视频与声呐数据契约

所有状态携带 schema_version、device_id、boot_id、seq、observed_at_utc；年龄用本机单调时钟计算并输出 age_ms，不跨主机比较单调计数。JSON 中 u64 标识采用十进制字符串。

| 对象 | 必备字段 | 语义 |
| --- | --- | --- |
| CameraStatus | channel_id、capture_state、publish_state、format、width/height、fps_observed、bitrate_observed、last_frame_age_ms、restart_count、error | fps 是测量值，配置 fps 另列 |
| StreamDescriptor | channel_id、path、codec、live_url、availability | URL 只含连接信息，不暴露管理凭据 |
| SonarSample | sensor_id、direction、address、seq、distance_mm、valid、reason、quality、age_ms | 不支持测距的成像声呐采用另一个类型 |
| Recording | recording_id、channel_id、start/end_utc、duration_ms、size_bytes、complete、locked、availability | 文件路径由服务器内部映射 |
| TimecodeStatus / TimeTag | epoch/seq、source_time_us、local_monotonic_us、observed_at_utc、quality、age_ms、mapping_id、timestamp_basis | 源时码/估计/无效区分；接口草案见RK时码设计 |
| SystemHealth | cpu、memory、temperature、disk_free、network、service_states、alerts | 可用字段按硬件能力标记 |

声呐 reason 建议为 timeout、crc_error、out_of_range、unconfigured、stale、device_fault；厂家原始错误码另列。质量未知用 null。具体过期门槛取配置的采样周期与超时预算，不能对不同型号统一假定。若声呐没有测量时间，仅记录收到时间。

## 4 RK API 草案

所有业务接口置于 /api/v1；反向代理统一网页与事件接口，媒体协议按所锁定版本配置。鉴权后的修改请求必须校验来源，避免浏览器跨站误操作。

| 方法与路径 | 功能 | 权限 |
| --- | --- | --- |
| GET /status | 全量系统快照 | 监看 |
| GET /streams | 六路描述及状态 | 监看 |
| GET /sonars | 五路最新读数与年龄 | 监看 |
| GET /timecode | 最新时码有效性、年龄、源epoch及接收映射质量 | 监看 |
| GET /events | SSE 状态变化与告警，断线后重新获取快照 | 监看 |
| GET /recordings | 通道/时间筛选、分页查询 | 录像读取 |
| GET /recordings/{id}/content | 完成片段读取，支持范围请求 | 录像读取 |
| POST /recordings/{id}/lock | 锁定或解除锁定 | 维护 |
| GET /config | 脱敏后的实际配置和 revision | 维护 |
| PUT /config | 带 expected_revision 的配置修改 | 维护 |

成功返回 data 与 request_id；失败返回 error.code、message、details。建议使用 CONFIG_INVALID、REVISION_CONFLICT、DEVICE_UNAVAILABLE、STORAGE_UNAVAILABLE。配置冲突返回 HTTP 409；校验错误返回 422。导出和删除只接受 recording_id，校验路径归属与符号链接，不把用户字符串直接拼接为文件路径。

API 不包含任何电机使能、运动或时间轴接口。SSE 只传状态，不传视频帧；建议状态 1Hz、告警立即推送，事件队列有界，慢客户端断开重建。不同监看客户端使用同一采集/发布源，不各自打开相机。

## 5 岸端视频界面

首屏显示时码源状态、epoch和有效/估计质量，以及一路可切换主画面和五路辅助画面，分别显示名称、连接状态和帧年龄；可在主画面旁看对应方向声呐读数。浏览器不可解码或没有新帧时显示原因并允许重连，冻结画面加离线遮罩。

录像页按通道和时间查询，显示录像缺口与锁定状态。维护页处理设备绑定、相机模式、声呐配置、存储策略与日志导出。观看不要求打开配置页；运行故障采用告警，不把调试寄存器或 GPIO 信息放进日常操作界面。

## 6 构建、启动与更新

### 6.1 镜像构建契约

当前独立入口为 `packaging/build-sdk-boot.py`、`packaging/build-image-rootfs.py` 和 `packaging/assemble-image.py`，输出 `output/ss07/<release>/`。构建及离线校验已实现，实际启动仍待验收，步骤见 [完整镜像构建](full-image.md)。保留 fusion-platform 及原有 SDK 入口，不复制其双 IMX287M 应用和 mscam-core 依赖。

| 步骤 | 输入 | 输出与检查 |
| --- | --- | --- |
| 版本锁定 | repo manifest、各 HEAD、板卡配置、工具链 | sources.lock；记录 dirty 状态，正式发布不混入未记录修改 |
| 内核与启动 | 当前源码、目标设备树/defconfig | U-Boot、内核、模块、DTB/extboot；检查实际编译日志 |
| 根文件系统 | 固定 Ubuntu ARM64 基础、包版本与媒体 ABI | 独立 rootfs；记录包版本，远端缺版本时构建失败 |
| 应用构建 | RK 服务/网页、媒体服务校验和、配置 | ARM64 程序/资产，动态依赖无缺失 |
| 集成 | systemd、设备映射、权限、网络、挂载 | 不启用旧相机测试服务；检查端口与外设冲突 |
| 打包 | 匹配分区表及所有新产物 | IMG、SHA256、版本清单、构建日志 |
| 烧录验收 | 完整 IMG、板卡与设备 | 冷启动及实际六路/声呐结果 |

现有 fusion build-image.sh 链接已编译 boot/uboot；SS-07 若要求当前代码完整镜像编译，必须先执行并核验对应源码构建。不得仅重打 rootfs 后声称启动组件已重编。不要盲目采用 output/defconfig 的 Focal 标记，明确实际基础系统与入口。

### 6.2 服务启动与应用更新

录像数据盘挂载成功是录像启用条件，不是整个媒体服务的启动条件；数据盘缺失时仍能监看并告警。网络可用后媒体服务拉取 SE2017；USB 通道依设备事件重试，不要求所有相机齐全才能启动。声呐和时码服务独立启动，缺时码不阻塞视频/声呐/录像。API 读取部分可用快照。

systemd 为采集服务仅授予所需 video/USB 设备权限，为声呐和只读时码服务分别授予各自串口权限；API 不持有这些外设。服务用专属用户，写入仅限状态、日志与录像目录。管理端口只在本机，网页和媒体按现场访问策略开放。

应用版本放 /opt/ss07/releases/<version>，配置、状态和录像在版本目录外。更新先校验签名/摘要及依赖，保留旧版本；停止受影响服务后切换 current，再检查健康，失败回滚。数据库迁移必须提供旧版本恢复路径，否则先备份后离线升级，不能简单回切程序。

RK 初期采用完整 IMG 加应用版本回滚，不假定分区已经支持 A/B 系统回滚。云台接收器单独交付，其更新不由本镜像构建或应用更新触发。


## 7 网络、电源与安装

候选 RK 地址192.168.20.10、SE2017 .20、岸端 .30、维护 .100，统一/24；固定实际网口身份，离线工作不依赖公网。媒体管理端口只在本机；网页、媒体与维护各有权限，日志不含凭据。

标准 LubanCat-4 裸板按5V/4A输入核验，图中的12V主控支路仅可用于带内部降压的机箱。Hub、交换机、编码器、声呐按实物电压独立供电，防反灌并测满载压降/温升。记录相机通道与Hub端口、声呐地址、串口身份、介质序号和配置版本。

## 8 本软件开发与验收

开发顺序：设备探测/身份绑定 → 单通道发布 → 六路汇聚 → 录像/索引 → 厂家声呐驱动 → 只读时码与记录关联 → API/网页 → 独立镜像 → 满载现场验收。建议后续目录为src/camera、src/sonar、src/api、web、config、systemd、packaging和tools，目前不创建占位实现。

| 验收 | 条件 |
| --- | --- |
| 六视频 | 冻结模式同时监看录像8小时，记录延迟、帧率、丢帧、资源与热，无持续增长 |
| 单路恢复 | 拔插/重启只影响该通道，恢复不交换相机方向 |
| 声呐 | 五地址有效采集，坏帧/离线不拖慢其他节点；验证真实采样与互扰 |
| 录像 | 完成片段可回放，缺盘不写系统盘，锁定不清理，满盘/拔盘/掉电行为明确 |
| 配置/API | 非法模式拒绝、版本冲突、生效失败恢复、只读/维护权限和路径校验 |
| 时码 | 三主机合法接线、RK只读、丢失/重启不阻塞录像、epoch隔离、媒体/声呐映射质量可查 |
| 独立性 | 杀视频进程/重启RK时现有跟焦和云台控制仍独立 |
| 镜像 | 当前源码启动组件/内核/rootfs构建记录，冷启动、身份、版本和应用恢复可复现 |

视频p95≤300ms和声呐每路≥5Hz为设备允许时的候选指标，待实测冻结。声呐型号、相机真实模式、实际存储和船岸线长是本软件待补输入。交付物仅为RK源码/应用包/网页、配置、systemd、完整IMG与摘要、版本清单、安装和验收记录。

## 9 只读时码与记录关联

新增时码服务、录像片段侧录索引与声呐接收时刻标签，具体字段、失时/恢复、epoch隔离与分级验收见 [RK时码接入设计](rk-timecode.md)。新增时码数据不修改原媒体PTS，不以采集接收时刻冒充相机曝光或声呐发射/测量时刻。
