# SS-07 时间轴编辑定位与位置查询方案

mobocon 在编辑时间轴时支持输入目标位置、单次定位、查询实际位置和确认关键点。连续手动运动由跟焦器遥控器或摇轮完成，PC 不发送连续摇杆目标。单次定位与只读查询都需要公共协议扩展，不需要高频 JOG/LIVE_SET 流。单次定位不需要时码。当前时码器只接mobocon/UE，原V1.2接收器授时播放流程需重新适配，见 [时码与播放边界](../timecode-integration.md)。

## 1 编辑流程

1. 在 mobocon 输入跟焦位置或云台角度，点击“移动到目标位置”；也可以用跟焦器或摇轮调整。输入/保存数值本身不触发运动。
2. 接收器校验能力、标定、范围、速度/加速度限制与控制源，受理一次有限时长的定位动作，由节点本地执行轨迹。
3. mobocon 低频查询，显示目标、实际位置、偏差、动作状态、数据来源、单位与有效性。ACK 仅表示受理，不代表到位。
4. 到位条件满足后操作员检查画面/焦点，确认保存关键点，再设置时间和过渡轨迹；动作失败或实际反馈不可用时不能显示“已验证到位”。
5. 按修订后的公共播放契约完成节目编译、下载、真实设备准备和启动；不直接沿用旧接收器授时T0流程，手动移动后的旧准备条件不能复用。

首版建议提供手动刷新，可选约 2Hz 自动刷新；最终按使用体验与串口负载调整，没有高频 PC 控制或 100ms 接受延迟要求。定位采用节点本地有界轨迹，与界面查询频率无关。运动执行期间降低查询优先级，不阻塞准备/中止事务。

## 2 位置数据与能力边界

| 值 | 来源 | 使用方式 |
| --- | --- | --- |
| 实际位置 | 电机编码器/厂家反馈或经过标定的独立位置传感器 | 有效且新鲜时可作为实际关键点 |
| 目标位置 | 接收器最近提交给电机的命令值 | 单独显示为目标，不能证明到位 |
| 遥控器输入 | NRF24 广播中的归一化值或摇轮数据 | 操作参考，不直接等同实际机械位置 |
| 无反馈 | 硬件/协议暂不支持实际位置查询 | 显示“实际位置不可用”，不填 0 或目标值冒充反馈 |

云台可从 CyberGear 类型 2 反馈或固件支持的 0x7019 负载端位置读取，统一为项目坐标与单位；核验机械零位、计圈、正方向、外部传动和固件能力。不能只取旧的缓存反馈而不显示年龄。

现有跟焦代码只输出 PDMOVIE 位置帧，未实现实际位置响应解析。需要确认该型号能否回传位置，并增加对应驱动；否则只能显示已发送目标或加独立传感器。若选择目标位置建立关键点，操作员必须明确选择，关键点记录来源，不自动替代“读取实际位置”。

## 3 PC 查询接口

V1.2 STATUS 固定 80 字节，包含节目/运行/授时状态，没有各轴实时位置；CAPS 描述能力/单位/限值，也不是位置采样。不要在 STATUS 尾部偷偷追加数据或把目标写入保留字段。

建议在 device_protocol 公共库登记只读设备遥测查询与能力扩展，保留现有 Control 帧、事务、地址与校验。命令码、TLV 编号、Payload 与发布版本在公共库设计时冻结，当前不将未实现 API 说成已存在。

查询回传至少定义：节点 UID/boot、资源/轴、单位、实际值可用标志、实际位置、目标位置、样本年龄、当前来源/运行状态、故障，以及对应标定版本。数值使用设备类别登记的 i32 单位；PC 将其转换为度或跟焦行程等界面值，不对不同单位混算。

节点缓存驱动反馈，PC 查询只读取状态快照，不每次串口请求都阻塞等待电机。反馈无效、过期、未标定或节点重启明确显示，无法取得实际值时不生成虚构读数。查询不使能电机、不改变来源、不触发校准、不使准备失效。

## 4 单次定位接口与执行

建议在公共库登记单次定位能力、启动及动作状态查询，沿用 Control 事务和去重机制；不能把 PROGRAM_COMMIT、DEVICE_PREPARE 或 STATUS 当成已有的任意位置控制 API。命令码、字段及 SDK 版本尚待公共库冻结。

启动请求至少绑定节点 boot_id、当前标定版本、唯一动作 ID、资源及目标、速度/加速度限制和执行期限。节点只允许一个定位动作，校验所有资源与完整路径后受理；忙时拒绝新目标，不排队积累旧目标。同 seq 重试和重复动作 ID 不得再次执行；状态查询按动作 ID 返回受理/运动中/到位/中止/故障，重连不自动重发动作。

接收器从有效实际位置规划有界轨迹；到位须连续新鲜反馈在各轴容差内，并满足类别定义的速度和稳定时间条件。容差、稳定时间及最大执行时间按具体电机/机构验收，不以固定等待时间推断成功。反馈丢失、超限或超时执行类别定义的停止/保持并报告失败。无实际反馈的跟焦只可开放明确标识的“目标下发/人工核对”能力，禁止宣布自动到位或已验证定位。

单次定位独立于时间轴授时，不要求为每次编辑启动一个 Run。接收器以本地单调时钟执行已受理的有限动作，Control 断开后最多完成该动作或在期限内停止，不接受后续目标；该策略不依赖 PC 心跳。断线后 PC 显示结果未知，重连查询原动作 ID。界面停止走公共停止事务与真实安全确认，物理急停独立有效。

## 5 时间轴关键点

关键点保存时间、资源、位置、单位、数据来源和标定版本。实际位置与目标位置在界面与保存流程中可区分。设备零位/行程标定变化后检查已有关键点有效性，必要时重新确认与编译，不静默改变物理含义。

保存关键点是编辑行为，不自动产生运动。正式节目通过公共编译器的范围、速度/加速度与协调组检查；位置位移采用符合类别约束的五次轨迹，不能把读取到的一串位置当作已经验收的机械路径。

## 6 仲裁与验收

接收器区分 SAFE、LOCAL_MANUAL、PC_POSITIONING、PC_TIMELINE，另保留故障与公共运行状态。只读查询不争抢运动来源；点击定位须明确取得节点控制权，无线帧不能在定位期间覆盖目标。定位结束保持当前目标，恢复无线需显式接管并清除旧待发目标，避免跳变。活动时间轴拒绝定位；切换须先中止并确认安全。定位或本地手动改变初态时调用公共 notify_state_change，旧准备失效，重新播放再准备。本地明确接管定位也须先中止动作并确认安全。

验收覆盖单次定位、范围/路径校验、到位反馈与超时、重复请求不重复运动、Control 断线和重连不重发、无线接管不跳变、活动时间轴拒绝定位、只读查询不引起运动、坏/过期反馈显示、目标与实际区别、节点重启/标定变化、手动刷新与低频轮询、查询期间无线操作正常、冻结后的时间轴控制不被查询阻塞、关键点单位与来源保存正确。

本方案为设计，尚未实现公共单次定位/遥测扩展、跟焦反馈解析或 PC 定位面板。实体时间轴的准备/安全反馈门槛仍需验证，低频查询不会消除这些硬件条件。
