# SS-07 云台接收器电机控制软件独立设计

本软件运行于云台接收器，接收摇轮 NRF24 输入及外部 mobocon 的 RS485 请求，控制 Yaw/Pitch/Roll 三台 CyberGear。软件独立编译、发布、烧写和验收，不依赖 RK3588 的进程或网络。现有跟焦系统只作为通信/硬件基础参考，不重新设计、不修改其固件。

## 1 功能边界与外部接口

| 接口 | 输入/输出 | 本软件负责 | 外部依赖 |
| --- | --- | --- | --- |
| 摇轮 NRF24 | 原始轮数据、状态、ACK | 校验、新鲜度、绑定、轴映射和本地运动 | 发送端实际载荷和手动控制语义 |
| PC Control RS485 | 时间轴、单次定位、位置/状态 | 公共协议适配、来源门控、真实执行与反馈 | mobocon 与公共库对应能力 |
| CyberGear CAN | 指令、反馈、故障 | 身份、模式、目标、保护及三轴遥测 | 实际固件、收发器和机械装配 |
| 显示/按键 | 状态、显式接管/维护 | 本地状态和授权入口 | 具体板卡/按键能力 |

不包含 PC 应用、跟焦电机驱动或独立发生器固件开发；时码器只接入mobocon与UE电脑，接收器不接时码器。初版为三轴位置控制及摇轮所需手动模式，不将电机位置环等同 IMU 稳定云台。若要求船体姿态补偿，另行增加 IMU 与稳定闭环设计。

保持已有 Receiver 的 PlatformIO/Arduino/FreeRTOS 工程基础，建立独立云台目标、配置和产物。可复用 radio、屏幕、配置与公共通信模块；PDMOVIE 发送任务不作为本软件的驱动。

| 模块 | 内容 | 后续目录建议 |

| WheelMapper | 轴绑定、方向、倍率、死区、限位与手动语义 | control/wheel |
| SourceArbiter | 唯一来源、世代、停止与接管 | control/source |
| PositioningExecutor | 一次有界轨迹、到位/超时/中止 | control/positioning |

## 3 任务和输出路径

无线任务与 PC 请求仅产生输入事件。来源仲裁和轨迹执行生成带 source、generation、resource、target、valid_until 的目标快照；唯一电机任务将其转成 CAN。旧世代目标被丢弃，切换来源清理尚未发送的命令。周期位置只保留最新值；使能、模式切换和维护命令按操作ID去重，不能被位置覆盖丢掉。

CAN RX独立解析并更新反馈；ISR只采样/唤醒，不执行协议业务或日志打印。Control任务负责公共应答；实时tick使用本地单调时钟，不接外部TimeCode。接收器本地保护与摇轮控制不依赖PC是否连接。UI/Flash和节目校验不阻塞电机刷新。

建议以1ms本地唤醒做台架评估，最终按Profile.update_gap、CAN吞吐和实测抖动冻结；不把调度周期当电机同步精度。节目验证另分配至少8KiB起始栈预算，按编译器报告和高水位验证。RAM/PSRAM容量、缓存、队列及驱动频率先测量，不沿用示例的固定容量。

## 4 来源仲裁

| 来源 | 接受的运动输入 | 行为 |
| --- | --- | --- |
| SAFE | 无普通运动 | 类别定义的安全态 |
| LOCAL_MANUAL | 已授权、新鲜摇轮输入 | 映射后受限位置/速度 |
| PC_POSITIONING | 一次已受理定位 | 节点本地有限轨迹 |
| PC_TIMELINE | 已授权时间轴请求（新契约待冻结） | 按确认后的播放模式执行 |

来源与公共下载/准备/运行状态正交。上电SAFE，不恢复旧目标、动作、Run或速度。切换为：请求 → 检查故障/急停 → 停原动作 → 确认真实安全 → 清队列并递增世代 → 授权。普通接管不能解除故障锁存。

活动时间轴拒绝编辑定位；需明确中止后再定位。摇轮接管也先停止本节点并确认安全，不自动停止外部跟焦系统。定位结束保持当前目标，显式交回摇轮后只接受新输入；绝对位置输入需要软接管/匹配，增量输入不补执行旧增量。具体按键和匹配门槛按发送端与装配冻结。

定位、手动或标定改变初态时调用notify_state_change，使旧准备token失效；重新播放重新准备。公共Run本身的正常输出不逐帧调用该接口。

## 5 摇轮手动控制

复用现有无线地址/频道/CRC基础，先取得真实发送端载荷，冻结每轴是绝对角度、增量还是速度，禁止把focus/zoom/iris字段直接解释为三轴角度。合法性、绑定、有限数和新鲜度均通过才进入仲裁；未知ts单位/回绕/重启语义先抓包确认。

增量/速度在节点积分并施加速度、加速度和软限位；死区、方向和倍率按配置。失联基于有效运动输入周期和机构测试设定，不能沿用通信重连阈值。恢复信号不继续旧速度、不隐式解除故障；切换电机模式先停止并确认。

## 6 CyberGear驱动与启动

生产候选主站ID=0，Yaw/Pitch/Roll为1/2/3，绑定各MCU唯一标识。原生CAN为1Mbps、29bit扩展帧、DLC8；不发送Word材料的AT串口封装。详细字段与手册疑点见 [CyberGear接口](../cybergear-interface.md)。

启动顺序：CAN初始化 → 逐轴身份/能力/故障读取 → 校验标定与姿态 → 停止状态下设置模式和限制 → 参数回读（能力允许） → 显式授权/使能 → 从有效当前位置接收新目标。身份冲突、反馈缺失或未知零位时禁止运动，不自动归零或设机械零点。

首版PC定位/时间轴采用位置模式；摇轮优先转为受限位置目标以减少模式切换，若发送端需要原生速度模式则单独验证切换与失联策略。项目单位为度/度每秒，驱动转rad/rad每秒；内部减速比不重复换算，外部传动单独配置。机械零位和类型18参数易失，启动重建不意味着可以恢复旧目标。

反馈解析类型2/21及固件支持的0x7019、0x701B、0x701C；核验计圈、量化和字节序。超范围值、错误节点、旧样本不能用于保持或判定到位。bus-off进入故障，恢复CAN后不自动恢复运动。

## 7 单次定位与位置查询

mobocon编辑时输入角度并点击移动，接收器本地生成有界轨迹。请求绑定boot、标定版本、动作ID、预期来源世代、轴集合/目标、速度/加速度和期限。首版一个节点同时一个动作，忙时拒绝，不积压或覆盖旧定位。

状态为ACCEPTED → MOVING → SETTLING → SUCCEEDED，另有REJECTED/ABORTED/FAILED。ACK只表示受理。到位需各轴连续新鲜反馈处于容差内，并满足速度/稳定时间条件；阈值按机械验收，超时/反馈失效执行停止或保持并报告失败。

查询约2Hz可选，只读原子快照，返回实际、目标、偏差、单位、标定版本、样本年龄、故障、来源和动作状态，不使能、不校准、不接管。定位执行频率独立于PC轮询。Control失联后已受理有限动作在本地期限内完成或停止；PC显示结果未知，重连查询原动作而不重发。

公共V1.2尚无这些完整接口，须消费公共库发布的定位/遥测/来源能力扩展；不追加固定STATUS字段、不自行占命令码、不修改vendor。动作重试不重复执行，结果过期返回UNKNOWN。完整行为见 [定位接口设计](../position-telemetry.md)，其中跟焦内容仅为外部系统参考。

## 8 无接收器时码输入的时间轴接入

时码器只接入mobocon与UE电脑。云台接收器没有TimeCode输入，不解析时码器帧，也不默认通过Control接收转发时码。摇轮、单次定位、查询与保护均按本地单调时间执行。

已读公共V1.2的缓存Run要求接收器授时LOCKED后绑定epoch/T0；删除接收器时码线后，不能直接调用原Run流程或关闭其检查冒充兼容。公共SDK仍锁定来源，消费者不修改vendor；真实三轴资源、单位、范围、速度/加速度、准备和安全反馈继续复用已确定的设备类别设计。

时间轴播放模式待确认：可以由mobocon按时码调度指令，或缓存轨迹后由mobocon触发接收器本地播放。前者需要定义周期目标/队列/迟到/中止与Control负载；后者需要定义启动、漂移、重同步和断线行为。当前不默认选择，不宣称现有SDK支持任一种新模式。

来源仍为PC_TIMELINE，实际开始/停止/故障条件在公共播放契约冻结后实现；活动时间轴与摇轮/编辑定位继续互斥。三轴共同软件更新不等于电机共同生效，CAN与电机延迟实测；不沿用旧授时设计承诺跨设备1ms同步。参考 [时码与播放边界](../timecode-integration.md) 及 [公共接口接入](../mobocom-integration.md)。

## 9 硬件、标定与保护

本固件需要一条PC Control RS485输入、CAN控制器及外部收发器。取消专用TimeCode接口、时码SOF捕获和接收器授时验收任务。实际MCU/原理图/GPIO未核验前不分配引脚；普通Control串口接收/方向控制与时码输入无关。

持久化保存schema、绑定、方向、零位、外传动、各轴软限位/速度/加速度、电流限制、标定版本和CRC；标定维护显式执行，先禁止运动，不逐帧写Flash。电机ID及标定必须与安装记录相符，换电机后不照搬旧标定。

CyberGear供电16至28V，检查满电和制动回馈。摇轮失联、反馈超时、硬限位/故障按类别停止；固件卡死或CAN断线必须由电机已验证看门狗/独立措施兜底。CAN_TIMEOUT的访问、单位、动作尚需台架确认。物理急停和失电姿态不依赖RS485事务能及时完成。

## 10 构建、交付与验收

独立云台PlatformIO目标锁定板型、工具链、Arduino/FreeRTOS与公共SDK；交付固件、摘要、引脚/板型配置、类别/标定schema、抓包向量、版本和验收记录。升级前停止并确认安全，启动不恢复旧动作；PC及RK包不包含本固件的自动烧写操作。

开发顺序：接口原型 → NRF24接收 → CAN单轴身份/反馈 → 单轴受限运动/停止 → 三轴与标定 → 来源门控 → 公共定位/遥测 → DeviceNode真实Hooks → 单独时间轴验收 → 与RK满载共存验收。

| 验收 | 必须证明 |
| --- | --- |
| 单轴/三轴 | 身份、方向、角度/计圈、范围、模式、反馈和负载真实正确 |
| 定位 | 单/多轴到位、超时、坏反馈、重复动作不重执行、停止完成 |
| 仲裁 | 摇轮/PC定位/Run互斥，旧世代丢弃，交接不跳变 |
| 时间轴 | 修订后播放模式的公共向量、准备/启动/终态、PC断线、重启和实测时间误差 |
| 失效 | 摇轮/Control分别断开；PC时码故障的上位机处理按冻结契约验证、CAN断线、bus-off、固件阻塞和电机故障 |
| 机械/电源 | 限位、配平、失电姿态、母线回馈、温升和实际停止时间 |
| 独立性 | RK断网/重启不改变来源或停止合法本地控制，现有跟焦不受影响 |

未确认项为接收器原理图/MCU、摇轮载荷、机械范围/负载、实际反馈能力与电机看门狗。它们决定引脚、参数和开放门槛；软件框架可以先开发，实体运动能力不能以示例值验收。
