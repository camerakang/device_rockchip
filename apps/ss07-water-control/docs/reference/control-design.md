# SS-07 接收器控制与授时详细设计

跟焦与云台共用协议、来源仲裁、轨迹和配置基础，分别实现 PDMOVIE 与 CyberGear 驱动。现有无线跟焦能力保持回归；接收器是电机输出的唯一决策点。公共单次定位与遥测扩展需要先在 device_protocol 发布，具体报文编号尚未冻结。

## 1 接收器模块与线程边界

| 模块 | 职责 | 执行边界 |
| --- | --- | --- |
| BoardProfile | UART/GPIO、收发方向、CAN、捕获、输入电压 | 每种硬件独立编译配置，不运行时猜引脚 |
| RadioAdapter | 原 NRF24 接收、合法性/新鲜度、轴映射 | 输出带序号和来源的输入事件，不写电机 |
| ControlAdapter | 公共 Stream、DeviceNode、请求尾时间、回复 | 串口任务，回复时间契约不变 |
| TimeCodeAdapter | 帧解析、实际 SOF 捕获、纪元和年龄 | 独立输入，禁止用解析时刻替代 SOF |
| SourceArbiter | 来源、世代、状态改变、按钮请求清理 | 单一执行者串行处理切换 |
| PositioningExecutor | 单次有限定位、范围/轨迹校验、结果 | 在节点本地生成目标，与 PC 轮询解耦 |
| TimelineExecutor | DeviceNode tick 与真实 Hooks | 独立于 Control 是否连接 |
| MotorBackend | 统一目标到 RS485/CAN、反馈与故障 | 唯一发送任务拥有外设 |
| TelemetryCache | 原子快照、有效标志、反馈年龄 | 查询只读取快照 |
| UI/Config | 显示、显式维护、标定版本、日志 | 不阻塞实时任务 |

可复用现有 FreeRTOS 任务，但必须去除无线回调直接更新最终电机目标的路径。ISR 只采样/记录/唤醒，不做轨迹校验、日志打印或协议业务。Control 校验节目使用专门验证任务及至少 8KiB 起始栈预算，最终按编译器报告/高水位实测；验证期间 tick 与授时继续运行。

每个目标包含 source、source_generation、resource_id、target、valid_until_local_us。切换来源递增 generation，发送端丢弃旧世代目标，并清理未发送按钮动作。发送队列有界，周期位置用最新快照；一次性维护/定位请求按操作 ID 去重，不能用覆盖快照丢失一次性命令。

## 2 来源与运行状态

| 来源 | 允许输入 | 电机目标产生方 |
| --- | --- | --- |
| SAFE | 查询、停止、符合条件的维护/复位 | 设备类别安全动作 |
| LOCAL_MANUAL | 有效、已授权无线输入 | 本地映射与限幅 |
| PC_POSITIONING | 已受理定位动作和停止 | 本地有限轨迹 |
| PC_TIMELINE | 有效公共 Run | 公共轨迹 tick |

来源与 DeviceNode 的下载/准备/运行状态正交。开机来源为 SAFE，不恢复任何旧目标、定位或 Run；绑定的遥控器可以显示在线，但必须显式启用本地控制。如何实现接管按钮由现有屏幕/手柄按键能力确认，不把第一包无线数据当隐式接管。

切换步骤统一为：请求 → 检查故障/急停 → 停止原动作 → 确认真实安全态 → 清队列并递增世代 → 授权新来源。安全确认失败维持故障并拒绝新运动。故障锁存不能由普通切换解除，CLEAR 仍遵守公共安全确认和复位条件。

时间轴活动时拒绝编辑定位。PC 明确中止后才能定位；无线接管先停止本节点并确认安全，不自动停止其他节点。定位动作结束保持当前位置，来源仍归 PC，显式交回无线后仅使用新输入；若手柄为绝对位置控制，需要软接管阈值/重新匹配，避免手柄旧位置造成跳变，阈值按机构验收。

## 3 定位扩展设计输入

以下是公共扩展应覆盖的语义，不是在 SS-07 私自分配 wire 命令。原帧格式、CRC、事务去重和窗口保持不变；扩展后的版本/兼容策略由公共库发布确定。

| 能力或操作 | 最小内容 | 受理条件 |
| --- | --- | --- |
| 定位能力 | 资源/单位、限值、反馈等级、可设速度/加速度、最长动作、到位参数 | CAPS 扩展可发现，旧节点不显示按钮 |
| 定位启动 | boot_id、标定版本、动作 ID、资源目标、限制、期限、预期来源世代 | 已授权、空闲、标定有效、目标和完整轨迹可证明 |
| 定位状态 | 动作 ID、状态、已运行时间、原因、到位判据状态 | 只读，受理与完成明确区分 |
| 位置遥测 | boot、标定、资源/单位、实际/目标、有效性、年龄、来源、故障 | 原子快照，查询不使能 |
| 来源交接 | 当前/预期世代、目的来源、交接结果 | 停止完成后才授权；编号与编码待公共定义 |

单次定位生命周期为 ACCEPTED → MOVING → SETTLING → SUCCEEDED，另有 REJECTED、ABORTED、FAILED。执行期间不接收覆盖目标，首版只允许一个动作；用户想改位置需先停止旧动作。多轴目标以一个请求校验，并在一个本地 tick 更新目标集合；真实电机共同生效能力另测。

动作 ID 在一个 boot 内去重；已完成动作保留最近结果，容量与保留时长作为能力契约冻结。结果已淘汰时返回 UNKNOWN，PC 不能自行推断成功。字段不足以装入单帧时在公共库定义受限资源数/分页，不改变 240 字节 Payload 上限。

## 4 真实设备类别

| 属性 | 跟焦 F | 云台 G |
| --- | --- | --- |
| 首版资源 | focus/R1 | yaw、pitch、roll |
| 界面单位 | 行程百分比候选 | 度 |
| 协议整数单位 | 行程万分比候选，登记后冻结 | 毫度候选，登记后冻结 |
| 驱动转换 | 已标定行程 → 0..7200；反向只在一层处理 | 项目角 → 电机 rad，零位与外传动映射 |
| 反馈 | 厂家实际反馈/独立传感器待确认 | 类型 2/参数读取，结合固件与计圈能力 |
| 准备 | 校准有效、使能、移至节目初态并确认 | 身份、零位、限位、姿态有效，移至初态并确认 |
| 停止 | 电机支持的停止/保持能力待验证 | 停止/保持/断电的真实机械行为按装配冻结 |

安全值不等于数字零。位置设备故障不得无轨迹归零；配平不充分的 Pitch 也不能默认掉电即安全。safe_targets、safe_confirmed、prepare_confirmed、terminal_confirmed、reset_allowed、run_allowed 必须按实际设备实现。没有真实反馈的 F 可以展示目标并人工核对，自动准备/终态/安全门槛没有解决前不开实体时间轴。

位置映射保存 calibration_id/version、方向、零位、上下限、外传动比及来源；写入使用版本和校验，不在每个 tick 保存 Flash。CyberGear 掉电易失参数与项目持久标定分别处理：启动按身份重建参数，但确认姿态前不使能运动，不在未知姿态设机械零点。

## 5 无线输入与云台手动

跟焦复用原始帧与 CRC；合法帧才能刷新运动年龄。ts 的单位、回绕、发送端重启语义需先抓包确认，确定后再实现重复/旧帧过滤；不能凭未知计数器自行拒绝全部帧。绑定 MAC/地址、频道、CRC 和有限数均通过后才进入来源门控。

云台摇轮须冻结每轴是绝对角、增量还是速度。若为增量/速度，接收器本地积分并施加速度、加速度和软限位，恢复连接不补执行旧增量。轮速滤波、死区、方向与倍率可配置，但首轮不假定 focus/zoom/iris 对应三轴。

无线失联时间基于有效输入周期及机构测试设定，不沿用 3000ms 重连阈值作为停机参数。速度输入失联逐步停止或硬停止由类别定义；跟焦取消目标后是否仍跑向旧位置必须实测。信号恢复不自动解除故障或恢复旧速度。

## 6 实时调度与容量预算

建议先以 1ms 本地调度唤醒做台架评估；实际 Profile.update_gap、轨迹采样与电机发送频率分别冻结，不能把 1ms 调度等同 1ms 电气同步。PDMOVIE 输出保持既有最大 100Hz；云台刷新频率按 CAN 负载与反馈测试选定。

| 项目 | 必须记录的预算 |
| --- | --- |
| RAM | 程序缓存、公共 Node、线程栈、UART/CAN 缓冲、遥测和显示；预留实测余量 |
| 验证 | 最长节目及复杂五次轨迹的校验耗时、栈高水位；异步 ACK 后查询结果 |
| 输出 | 队列等待、总线发送、电机响应、反馈延迟、三轴偏差 |
| 时钟 | 接收延迟标定、SOF 捕获误差、tick 抖动、保持边界 |
| 优先级 | 电机保护与实时执行高于 UI/Flash；协议应答不能被长任务饿死 |

程序最长 600 秒不等于固定缓存足够；按实际编译字节数检查 CAPS 容量，超出直接拒绝。容量选择需读板卡 RAM/PSRAM 与公共模板实例测量后冻结，不拿示例 DeviceNode<4096,...> 当成产品值。

CAN 使用扩展帧过滤身份/目标节点，处理总线错误与 bus-off，不无条件自动恢复运动。反馈关联电机 ID/UID，错误 ID、故障温度、电压和过期数据都会阻断相应运动能力。详见 [CyberGear 设计](../cybergear-interface.md)。

## 7 时间码发生器

发生器拥有稳定单调时钟、boot/epoch、序号及独立 RS485 输出，每 10ms 按公共格式发帧。epoch 每次重启变化，不使用 UTC 作为节目时基。发送时间指 SOF 实际起始；定时器、DMA/UART 启动与线驱动延迟须标定，不能只在写函数之前读取时间。

PC 管理旁路建议独立 USB，读取 epoch、当前时间、同步状态、误差界及版本；旁路不向电机发送目标。可信时钟的交换、往返延迟界和设备排队上界另定义并测量；无法形成可信上界时禁止自动启动/启动失败自动取消，不把 USB 到包时刻当可信时钟。

F/G 的 SOF 捕获需选择实际板级方案：硬件边沿捕获加 UART 帧关联，或芯片提供的有界硬件接收时间。UART 软件收到整帧再倒推长度不自动满足要求，需证明中断/缓冲误差与坏帧关联。能力声明与实际接线一致，不能两个输入交替授时。

## 8 独立故障链

主控固件卡死时软件停止不可达，必须验证电机自身看门狗或独立硬件措施。CyberGear CAN_TIMEOUT 的单位、访问和机械动作未确认，列为开放运动前的台架门槛。物理急停的制动与电源切断顺序按配平/负载设计，不能盲目断电导致姿态坠落。

日志使用独立通道，记录 boot、来源世代、动作/Run ID、状态改变与故障原因。串口/USB 二进制流中不混入 printf 文本；实时路径只写有界日志事件。共享 Control 的停止仍受事务窗口约束，独立物理保护不等待该窗口。
