# 0.9.0 与 0.10.0 的配置迁移和恢复

2026-10-24。本增量实现已识别的旧数据契约与声呐契约之间的安装迁移。0.10.0 的 config 兼容修订为 2，JSON envelope 仍为 schema 1；视频 catalog=2、时码 journal=1 和账户/审计格式保持原版本，声呐诊断、归档索引及卷侧录各为 schema 1。本路径不转换未知数据库或厂家协议。

## 识别与预检

包导入只接受两个完整、匹配的契约：旧版的八个数据类别和十个单元，或声呐版的十一个类别和十一个单元；未知类别、错误整数类型、未知 schema 或不匹配的文件/单元集合均拒绝。旧 0.7.0 无显式契约的特例仍仅限既有精确摘要。迁移实现不执行来自归档的安装脚本，依然逐文件核验摘要和路径。

新版本声明 `reviewed_sonar_config_transition_v1`。仅这次已实现的契约转换可跨修订安装；声明兼容或版本号相近均不构成通用迁移许可。请保留 0.10.0 的独立维护工具，降级后也用其绝对路径调用，避免活动链接切回旧版后误用不认识新事务的旧安装工具。引导恢复助手继续保留在 `current` 之外。

跨契约预检先读取并验证已保存候选和运行配置，在临时根中用目标版本自己的 `validate` 命令验证迁移后的配置，再准备安装事务。未通过前不改写任何运行配置。切换前停止配置协调器及消费者，重新检查配置和历史的原始字节，拒绝并发写入产生的漂移。

## 升级

旧版升级到声呐版时，保留两份配置的原始字节；新增归档字段缺省 false，不自动开启录像或采样，不补 UART、声呐地址或数据盘 UUID。配置恢复和启动门控中增加声呐服务。原 target 已在运行时才加入新服务；只启用了部分服务时维持原有启用范围。

厂家注册表仍为空。声呐服务保持明确不可用，无测距值，不打开 tty 或数据盘归档写者。此迁移不是厂家驱动或实物验收。

## 降级

降级必须同时满足候选和运行配置中的 `sonar_recording_enabled` 都为 false 或缺省；任一为 true 都在服务动作之前拒绝，返回 `sonar_archive_must_be_disabled_before_downgrade`。可先通过当前版本将声呐归档关闭并明确应用；关闭仅重启声呐/API，不因该字段单独重启视频录像或维护进程。厂家驱动缺失时仍允许这一关闭操作，开启继续拒绝。

降级仅移除明确为 false 的新增字段，保留其他配置值及文件所有者、组和权限。JSON 排版可能规范化，配置摘要因此可以变化；不会把旧的摘要当作已确认的新配置。

配置协调器的最后一次已完成事务可能引用新字段的摘要或 sonar 服务结果，旧程序无法解释。迁移只在事务处于 APPLIED、ROLLED_BACK 或 FAILED、运行配置摘要一致、两份历史快照完整且各自通过 schema/摘要验证时，归档其 `transaction.json`、`previous.json` 和 `candidate.json` 的原始字节，再从运行目录移除。无事务的残留快照也需通过配置校验。旧协调器以当前配置重新开始；候选仍可保持待应用。配置审计数据库完整保留，原事务可从本次安装的只读私有备份中核查。未完成事务、缺失快照、摘要漂移和损坏历史均不会被清空来绕过恢复。

声呐单元从目标运行集合和受管单元文件中移除，原声呐用户、索引、诊断库、卷文件和侧录均保留。旧版不会继续声呐采样；再次升级仍可使用保留的数据。不回滚数据库快照来覆盖降级前后新增的记录。

## 失败与启动恢复

两种方向都先保存持久 `PREPARED` 事务、`file-N` 原文件备份及 `migration.json` 收据。原备份编号不变，新增三个配置历史路径只附加到表末尾。新安装事务始终核验并一致备份包括声呐在内的已知数据库，旧消费者不会因此获得声呐写入权限。

配置、历史、单元和版本收据的每个替换/删除均写入同一安装事务；启动失败或未完成安装的启动恢复，会恢复原代码指针、配置字段、历史、所有者和权限。迁移及恢复均不覆盖原始录像、声呐文件或兼容数据库中新增加的数据。未知声呐 schema 保留门控，要求明确的离线迁移。切换期间出现外部配置修改时，拒绝覆盖该修改并保留恢复错误。

每次收据保存在 `/var/lib/ss07-deploy/transactions/<operation_id>/migration.json`，与原始文件备份和数据库一致备份同属一个事务目录。保留历史的数量/空间门槛沿用原安装器，不自动删除版本、记录或备份。

## 软件验证范围

验证包含：完整旧契约导入、升级时配置字节保持、部分启用范围、降级字段与权限、已完成历史归档、声呐数据保留、失败恢复、启动中断、归档开启拒绝、关闭操作的选择性重启、未知 schema、未完成配置事务和前后两个时点的配置漂移。具体结果见[迁移验证记录](evidence/sonar-migration-validation.json)。

精确应用包与真实本机进程联测使用合成媒体和隔离卷；ARM64 包与系统服务分别进行隔离用户态和静态验证。它们不证明板端实际 UID、USB/RS485、电气零 TX、实盘掉电、整机八小时负载或新内核启动。后续已生成包含此增量的 0.10.0 完整 IMG 并通过[离线回读与用户态验证](evidence/full-image-0.10.0-validation.json)；真实设备部署及烧写仍等待明确指令，实物验收未完成。
